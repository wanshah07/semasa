## Authority and precedence

This is a **requirements snapshot**, not a claim that every creative output or optional backend is verified. Source **U** is Wan's agreement supplied with this audit: “make sure all format videos we agreed previously are applied to semasa system”, followed by the detailed A–D/design/brand/audio requirements in the task handoff. That handoff is the source for the exact personal name and CTAs; no credentials were inferred. Source **R** is the checked-in reference set [`rules/motion/designs/README.md`](../../rules/motion/designs/README.md), its approved v17 continuous-line HTML and v16 provenance/script files. Source **S** is the original full [`Styles.docx`](Styles.docx), [`Styles.txt`](Styles.txt), imported section/effect/provenance registries and [native roadmap](native-effects-roadmap/checklist.md). Source **V** is current-main PR81/82/83, especially PR83's explicitly disclosed Kitten-to-Edge fallback when the runner has no VoiceStudio installation.

**Latest wins:** U/v17 supersedes old no-CTA/no-logo rules, 171wpm English, 10s explainers, narrated text merely muted, recurring WS headers and all formats sharing the corporate logo. V permits the already-approved, **disclosed** English Edge fallback; it is not called VoiceStudio in the result. Personal LinkedIn overrides general language/ratio/corporate CTA settings. The two preserved designs are independent from full-video recipes and from individual effect selections.

The executable shared contract is [`video-format-policy.json`](../../rules/motion/video-format-policy.json). Both JS and Python consume it. `options.format` is authoritative; legacy mode/language/voice infer a format only when no valid format exists. Saved defaults are normalized, not migrated in a live database. Unknown/unsupported runtime capabilities do not make the four basic choices disappear.

## Entry-point and worker verification boundary

`test_video_format_worker_paths.py` executes the real JS form/idea/draft helpers and passes those serialized jobs through real worker normalization, planning orchestration, fitting, composition and persistence for **4 formats × 2 designs × 3 helper entrypoints = 24 configurations**. The writer, voice, renderer and storage in this unit/integration test are **explicit doubles**, not fabricated end-to-end production evidence. Composer and bulk use those same tested helpers; source-level guard tests protect their existing wiring.

`ops/smoke_video_formats.py` separately invokes cached real HyperFrames, real FFmpeg mix/preview and full decode for authored offline silent30s/gimmick10s fixtures. It makes no model/TTS calls. Success is renderer-path evidence, not proof of fluent generated narration, real BM pronunciation, personal-avatar approval, stock licensing or an end-to-end UI session. Full acceptance still requires visually reviewing representative generated videos with actual available voices/assets.

## Archive integration gate

Keep status **pending / unconfigured** until the user authorizes an account/folder and chooses the integration route. An implementation must upload master/preview plus provenance and policy metadata, read back the exact remote object, verify its size/checksum, persist archive IDs/receipt, and only then permit local cleanup. Failures retain local artifacts and report a retryable error. Do not use local filesystem writes as fake Google Drive uploads, and do not claim the queue request configured a credential or job.

## Remaining runtime gates

- Actual VoiceStudio installation or the disclosed current-main Edge fallback must be available; a failed requested voice now blocks rather than silently producing a muted voiced explainer.
- Actual own avatar must be uploaded and saved for personal LinkedIn defaults; absent/corrupt still blocks before any writer call.
- SadTalker, clone and Drive remain unconfigured. Uploaded-footage editing is unsupported by this generator. Automatic licensed stock sourcing remains unconfigured; native diagrams/manual cleared assets remain available.
- Both writer prompts carry qualitative constraints, but no finite set of prompt assertions proves scientific truth, natural pronunciation, complete prose, face-safe composition, or visual fidelity of every generated output. Do not report “all E2E passed” without actually rendering and inspecting those outputs.
